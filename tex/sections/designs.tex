\section{Two Interrupt Policies}\label{sec:designs}

We now instantiate the model with two interrupt policies: \m{model_immediate}, which
leaks (\cref{sec:leak}), and \m{model_sliced}, which does not (\cref{sec:sliced}).
Both are exercised on the same concrete system. Its public user process
emits the request \code{GetRequest} (\code{Get}) whenever it runs, and its private
user process emits \code{Syscall} (\code{Sys}) when the disk handler has notified it
and \code{Idle} otherwise. The scheduler alternates between the two user processes.
Handlers take $\mathit{runtime} = 2$ steps.

Each step is taken by one of three kinds of process: the users or the scheduler
(U), the timer handler (T), or a secret handler, disk or NOP (S). The attacker sees
the U and T steps (\cref{fig:system}). Of an S step it sees only that it happened:
the public slots stay silent, and nothing shows which secret handler ran. It thus
learns when the system enters S and how long it stays there, so for the attacker to
learn nothing, both must be fixed by public events; what runs inside S may depend on
the secret. \Cref{fig:policy-ordinary,fig:phases} draw the two policies over U, T and
S, and \cref{fig:run-ordinary,fig:run-sliced} run them on the same inputs.

\subsection{Ordinary interrupt handling, and the leak}\label{sec:leak}

\m{model_immediate} services an interrupt as soon as no handler is running
(\cref{fig:policy-ordinary}). A pending timer interrupt takes the system from U to T,
and a pending disk interrupt takes it to S, from U or from T, at whatever step it
arrives. Each completion unmasks everything and moves on to the next pending handler,
or back to U. The two bold arrows into S are the leak: the secret decides when S is
entered.

The initial state
\begin{lstlisting}
immediate_init :=
  ((initial_pid, None),
   (false, (None,        (* slice counter *)
    ((false,false),      (* NOP *)
     ((false,false),     (* disk *)
      (false,false)))))) (* timer *)
\end{lstlisting}

starts in the public user with the slice counter disabled (fields as in
\cref{sec:global-state}). The interrupt controller holds one (pending, mask) pair
per handler, and all six bits start clear. The service policy is a single stage,
which reacts to any handler finishing:
\begin{lstlisting}
immediate_service o v :=
  if is_ir_out_done o is Some ir then
    let v := unset_masks v in
    if ir is timer_irq then update_re_sched v true
    else v
  else v
\end{lstlisting}
\m{is_ir_out_done} names the handler, if any, that emits \code{Notify} in the output
\code{o}. The service policy then unmasks everything, and after the timer handler
also requests a reschedule. It thus reads the output of whichever handler completes,
the disk handler's included. \m{restore_invariant} is the identity.

The run with the disk interrupt in \cref{fig:run-ordinary} shows the policy at work.
The pid of each step is computed at the output of the step before (\cref{sec:state}).
The disk interrupt arrives after step 1 and only sets the disk pending bit, so step 2
still belongs to the public user. At the output of step 2, \m{initiate_next} finds
the disk handler pending and unmasked and starts it, setting all masks: U to S. The
timer interrupt that arrives meanwhile stays pending until the disk handler emits
\code{Notify} at step 4: S to T. The timer handler's completion at step 6 requests a
reschedule: T to U, where the scheduler hands step 8 to the private user. Without the
disk interrupt the system never enters S. Its two steps are taken from the public
user, and the masks, which are public, are set at steps 3 and 4 in one run only.

\begin{theorem}[\m{model_immediate_not_NI}]\label{thm:leak}
For the concrete system,
\[
\mathsf{model\_immediate\_concrete} \notin
  \NI(\mathsf{in\_equiv},\, \mathsf{out\_equiv}).
\]
\end{theorem}

\begin{proof}[Proof sketch]
Let $p$ be the model and $o_G$ the output in which only the public slot is set, to
\code{Get}. The model performs $\perf{p}{!o_G.!o_G}{\Lo}$. The disk interrupt is
unobservable at $\Lo$, so insertion demands $\perf{p}{?\mathsf{disk}.!o_G.!o_G}{\Lo}$.
Reduction is deterministic (\cref{sec:background}): $p$ has exactly one input step on
\textsf{disk} and every process exactly one output step, so we only need to follow
that run. The input step $\stepI{p}{\mathsf{disk}}{p_1}$ sets the disk pending bit and
leaves the pid at its initial value, the public user. So the output step
$\stepO{p_1}{o_1}{p_2}$ emits $o_1 = o_G$, and at its end \m{initiate_next} finds the
disk handler pending and unmasked and sets the pid to the disk handler: U to S. The
next output step $\stepO{p_2}{o_2}{p_3}$ is the disk handler's, so $o_2$ has
\code{None} in the public slot, and $o_2 \not\eqv{O}_\Lo o_G$.
\end{proof}

\subsection{Sliced interrupt handling}\label{sec:sliced}

The sliced policy removes the bold arrows. It runs the secret handlers only in
\emph{time slices}: S is entered only when the timer handler completes, and the
system stays there for a fixed number of steps (\cref{fig:phases}). A slice holds
exactly $\mathit{runs}$ handler runs ($\mathit{runs} = 2$ in the concrete system), and
a run that no disk interrupt claims is taken by the NOP handler, so a slice is the
same whether or not a disk interrupt is waiting. Each part of the policy below
removes an arrow of \cref{fig:policy-ordinary} or fixes how long S lasts.

The slice counter tracks the slice. Outside it, in U and T, the counter is
\code{None}. In S, \code{Some n} counts the $n$ steps left, and \code{Some 0} marks the
last step, at whose output the slice closes. Closing must happen once. With a plain
number, \code{0} could not tell a closing slice from a closed one, and closing on
every step outside a slice would unmask the timer while its own handler runs.

The initial state masks the disk and NOP handlers, so no disk interrupt can take the
system from U to S, and leaves the timer unmasked:
\begin{lstlisting}
sliced_init :=
  ((initial_pid, None),
   (false, (Some 0,      (* slice counter *)
    ((false,true),       (* NOP *)
     ((false,true),      (* disk *)
      (false,false)))))) (* timer *)
\end{lstlisting}
Its counter, \code{Some 0}, is an empty slice that closes at the first output and
changes nothing else.

The service policy runs three stages on each output, right to left:
\begin{lstlisting}
sliced_service runtime runs o :=
  check_slice_count
  (@$\circ$@) check_handler_completed runtime
  (@$\circ$@) initiate_ir runtime runs o
\end{lstlisting}
The first stage is the ordinary policy's single stage restricted to the timer
handler, whose output is public. It keeps the reschedule and, instead of unmasking,
opens the slice, the only way from T to S:
\begin{lstlisting}
initiate_ir runtime runs o v :=
  if tI_out o is Some Notify then
    update_re_sched
      (update_slice_count v
         (Some (runs * runtime)))
      true
  else v
\end{lstlisting}
When the timer handler emits \code{Notify}, it loads the counter with
$\mathit{runs}\cdot\mathit{runtime}$, the number of steps that $\mathit{runs}$ handler
runs take, and requests a reschedule, which returns control to U, through the
scheduler, once the slice is over. The second stage acts at the boundaries between
runs:
\begin{lstlisting}
check_handler_completed runtime v :=
  if handler_completed runtime
       (get_slice_count v) then
    update_ir_pending (set_tI (unset_masks v))
      nop_irq true
  else v
\end{lstlisting}
\m{handler_completed} holds when the counter is a nonzero multiple of
$\mathit{runtime}$: when the slice opens and after each completed run inside it.
Unmasking has moved here from the first stage: it happens at boundaries computed from
the public counter, not on completion signals. Since every run takes
$\mathit{runtime}$ steps, the two fall on the same steps; only the reason has
changed. There the masks reopen, but the timer is masked again, so it cannot leave S early,
and the NOP handler becomes pending. That last step is the \emph{filler}: a handler
is always ready at a boundary, so S is entered and every run of the slice takes place
whether or not a disk interrupt is waiting. A pending disk handler takes priority;
which of the two runs is all the secret decides. The third stage, \m{check_slice_count},
ticks the counter, and at \code{Some 0} closes the slice: it masks the disk and NOP
handlers, so U cannot lead to S, unmasks the timer and disables the
counter.\footnote{With one-step handlers the last run of each slice is lost
(\cref{sec:restore}); non-interference is unaffected.} \m{restore_invariant} only
matters to the proof (\cref{sec:restore}).

In \cref{fig:run-sliced} the slice opens at the output of step 6, which is also its
first boundary, so S runs steps 7 to 10 in both runs, and the scheduler runs at step
11. The runs differ only inside S, in which handler fills the first run, and in what
the private user emits afterwards. By \cref{fig:system}, the attacker sees neither, so
the two runs look the same to it. The same holds for any two runs that differ only
in inputs the attacker cannot see:

\begin{theorem}[\m{model_sliced_NI}]\label{thm:main}
If the scheduler and the public user process are non-interfering at
\m{public_equiv} on input and output, and the private user process is
non-interfering at \m{private_equiv} on input and output, then
\begin{multline*}
\mathsf{model\_sliced}\;\mathit{runtime}\;\mathit{runs}\;p_{pub}\;p_{priv}\;p_{sched}\\
  \in \NI(\mathsf{in\_equiv},\, \mathsf{out\_equiv}).
\end{multline*}
\end{theorem}

An attacker who sees only the two user processes, and not the scheduler or the
handlers, observes \m{model_sliced_userview}, which applies \m{parse_output} to
every output to erase all but the user slots.

\begin{corollary}[\m{model_sliced_userview_NI}]
Under the same hypotheses, \m{model_sliced_userview} is non-interfering at
\m{out_equiv_userview}.
\end{corollary}

The corollary follows from \cref{thm:main} by \m{map_NI}, since \m{parse_output} maps
\m{out_equiv}-related outputs to \m{out_equiv_userview}-related ones.
