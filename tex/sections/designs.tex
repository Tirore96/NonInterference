\section{Two Interrupt Policies}\label{sec:designs}

We now instantiate the model with two interrupt policies. The first,
\m{model_immediate}, handles
interrupts the ordinary way: a handler starts as soon as its interrupt can be
serviced. It leaks (\cref{sec:leak}). The second, \m{model_sliced}, runs handlers
only inside time slices opened by the public timer, each slice holding a fixed number
of handler runs, with unused runs filled by the NOP handler. It does not leak
(\cref{sec:sliced}). \Cref{fig:schedules} runs both on the same inputs.

Both are exercised on the same concrete system. Its public user process
emits the request \code{GetRequest} (\code{Get}) whenever it runs, and its private
user process emits \code{Syscall} (\code{Sys}) when the disk handler has notified it
and \code{Idle} otherwise. The scheduler alternates between the two user processes.
Handlers take $\mathit{runtime} = 2$ steps, and the sliced policy uses slices of
$\mathit{runs} = 2$ handler runs.

\subsection{Ordinary interrupt handling, and the leak}\label{sec:leak}

\m{model_immediate} is \m{model} at
\begin{lstlisting}
immediate_init :=
  ((initial_pid, None),
   (false, (None, false_ic)))

immediate_service o v :=
  if is_ir_out_done o is Some ir then
    let v := unset_masks v in
    if ir is timer_irq then update_re_sched v true
    else v
  else v
\end{lstlisting}
and the identity for \m{restore_invariant}. In \m{immediate_init} (fields as in
\cref{sec:global-state}) the slice counter is \code{None}, disabled, and
\m{false_ic} clears every pending and mask bit.
\m{is_ir_out_done} names the handler, if any, that emits \code{Notify} in the output
\code{o}; the service policy then unmasks everything, and after the timer handler
also requests a reschedule. An interrupt is therefore serviced at the first output
step after it arrives at which no handler is running, and nothing constrains
\emph{when} that is. \Cref{sec:state} traced the consequence: the disk handler
starts at once and takes the public user's steps, producing the gap of
\cref{fig:leak}.

\begin{theorem}[\m{model_immediate_not_NI}]\label{thm:leak}
For the concrete system,
\[
\mathsf{model\_immediate\_concrete} \notin
  \NI(\mathsf{in\_equiv},\, \mathsf{out\_equiv}).
\]
\end{theorem}

\begin{proof}[Proof sketch]
Start from the trace of two public requests, which the model admits. Insert a disk
interrupt at the front; it is unobservable at $\Lo$, so non-interference demands
that the result still be a trace. It is not. The interrupt sets the disk pending bit.
The pid of the first step was fixed before any input, so the first request still
goes through; but the next step belongs to the disk handler, so the public slot carries \code{None} where the second request was.
\end{proof}
A single counterexample refutes non-interference, so ordinary interrupt handling is
not non-interfering in general.

\subsection{Sliced interrupt handling}\label{sec:sliced}

The idea is to take away a secret interrupt's power to choose when its handler runs.
Time is cut into slices, and a slice is opened only by the timer handler finishing,
which is public. Each slice holds exactly $\mathit{runs}$ handler runs (for handlers of at least two
steps; \cref{sec:restore} discusses one-step handlers), and a run that no disk
interrupt claims is taken by the NOP handler.

\m{model_sliced} is \m{model} at \m{sliced_init}, \m{sliced_service} and
\m{restore_invariant}:
\begin{lstlisting}
sliced_init :=
  ((initial_pid, None),
   (false, (Some 0, mask_most)))

sliced_service runtime runs o :=
  check_ir_count
  (@$\circ$@) check_handler_completed runtime
  (@$\circ$@) initiate_ir runtime runs o

initiate_ir runtime runs o v :=
  if tI_out o is Some Notify then
    update_re_sched
      (update_ir_count v
         (Some (time_slice runtime runs)))
      true
  else v

check_handler_completed runtime v :=
  if handler_completed runtime
       (get_ir_count v) then
    update_ir_pending (set_tI (unset_masks v))
      nop_irq true
  else v

check_ir_count v :=
  match get_ir_count v with
  | Some n.+1 => update_ir_count v (Some n)
  | Some 0 => update_ir_count
                (set_otherIs (unset_tI v)) None
  | None => v
  end
\end{lstlisting}
The system starts outside a slice: \m{mask_most} masks the disk and NOP handlers
and leaves the timer unmasked. The slice counter \m{ir_count} counts output steps,
and \m{sliced_service} runs three stages on each output, right to left:
\begin{itemize}
\item \emph{Opening a slice.} When the timer handler emits \code{Notify},
  \m{initiate_ir} loads the counter with
  $\mathsf{time\_slice}\;\mathit{runtime}\;\mathit{runs} =
  \mathit{runs}\cdot\mathit{runtime}$, the number of steps that $\mathit{runs}$
  handler runs take, and requests a reschedule for when the slice ends.
\item \emph{Boundaries.} \m{handler_completed} holds when the counter is a nonzero
  multiple of $\mathit{runtime}$: at the start of the slice and after each
  completed run inside it. There \m{check_handler_completed} reopens the masks,
  masks the timer again, and makes the NOP handler pending. That last step is the
  \emph{filler}: a handler is always ready at a boundary, so a run takes place
  whether or not a disk interrupt is waiting, and the disk handler, if pending,
  takes priority.
\item \emph{Closing.} \m{check_ir_count} ticks the counter, and when it reaches
  zero masks the disk and NOP handlers, unmasks the timer and disables the counter.
\end{itemize}
On the step where the timer handler completes, opening a slice and its first
boundary coincide, so the first run of the slice starts at the very next step.
Outside a slice a disk interrupt is only recorded as pending; inside one, the
timer is masked, so it cannot start a handler mid-slice. When a slice ends, the
reschedule requested at its opening hands control to the scheduler.

A secret handler run therefore takes the place of a NOP run: a slice containing a disk run has the same length and position as one
containing only filler, and the public schedule around it is unchanged.
\Cref{tab:traces} shows this on the concrete system. The two runs differ only in a
disk interrupt; it is recorded as pending, waits for the next slice, and then
replaces the first NOP run. Only two rows differ: one in which handler ran, and one in
the private user's value. By \cref{fig:slots}, the attacker sees neither, so the two
runs look the same to it. \Cref{thm:main} in \cref{sec:proof} proves that the same holds
for any two runs that differ only in inputs the attacker cannot see.
