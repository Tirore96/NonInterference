\section{The Security Proof}\label{sec:proof}
This section proves that the sliced policy is non-interfering, with $\Ein$ and
$\Eout$ of \cref{def:io}:

\begin{theorem}[\m{model_sliced_NI}]\label{thm:main}
If the scheduler and the public user process are non-interfering at
$\pubeq$ on input and output, and the private user process is
non-interfering at $\priveq$ on input and output, then
\[
\mathsf{model\_sliced}\;\mathit{runtime}\;\mathit{runs}\;p_{pub}\;p_{priv}\;p_{sched}
  \in \NI(\Ein,\, \Eout).
\]
\end{theorem}

\subsection{The state equivalence}\label{sec:state-equiv}

\todo{$\eqv{V}$ is given only by the shading of Fig.~4 and the bullets below.
Give it a definition like Definition 3 ($\eqv{V} \triangleq \dots$, one factor

For the state, \comp{it:sta} asks for $f \in \mathsf{PE}(\eqv{E},\eqv{V})$, so an
unobservable event leaves the state related to itself, and $f \in
\NI(\eqv{E},\eqv{V},\eqv{V})$, so related events take related states to related
states (\cref{sec:composition}). The first condition asks for private fields, the
second for public ones. We make a field private only
where a condition forces it, which gives $\eqv{V}$, the shading of \cref{fig:state}
(\m{state_type_equiv}):
\begin{itemize}
\item \emph{Pending bits are private.} A disk interrupt is unobservable at $\Lo$ and
  sets the disk pending bit, so $f \in \mathsf{PE}(\eqv{E},\eqv{V})$ makes that bit
  private. The NOP pending bit is private by $f \in \NI(\eqv{E},\eqv{V},\eqv{V})$:
  when a slice opens, the disk handler takes the
  run the NOP handler was queued for, so after that run the NOP handler is pending
  in one state and not in the other.
\item \emph{The current pid is $\privvis + \pubeq$.} Its
  \code{inl} side holds exactly the two secret handlers (\cref{sec:global-state}),
  and which of them runs may differ between the two states, so the value inside
  \code{inl} is private. The $^\circ$ makes no \code{inl} unobservable, so
  the sum never relates an \code{inl} to an \code{inr}, and \emph{whether} a secret
  handler runs stays public.
\item \emph{Every other field is public:} the masks, the slice counter, the
  reschedule flag and the previous pid. Nothing forces them private, and
  \m{initiate_next} branches on all of them to compute the next pid, whose tag
  must be public: two states that disagreed on a mask, or on whether a slice is
  open, could enter S in one and not in the other.
\end{itemize}
The same conditions explain why \m{set_pending} sets one bit and stops: any decision
taken on an input step, such as starting a handler or moving the counter, would
change a public field, so everything an interrupt causes waits for a later output
step.

The first five read only public fields of the state and public slots of the
output, so on related arguments they write the same values, private bits included,
and their obligations are routine. The service policy, stages 2 to 4, reads only
the timer handler's output; this is what the restriction of \cref{sec:sliced} buys.

readiness is public, so both states agree on it. Otherwise, in each state the
secret handler ready to start is the disk handler, the NOP handler, or none. Disk in
one state and NOP in the other is harmless: both start an \code{inl} pid, whose
value is private. A secret handler in one state and none in the other is fatal: one
state enters S and the other continues a user process.

\subsection{Restoring the invariant}\label{sec:restore}

The output lane is one function of the output and the state, the composite of the
six stages of \cref{sec:update}. Proving it non-interfering in one piece would mean
following all their branches at once. \m{fv_NI_comp} instead proves it stage by
stage: if every stage takes related arguments to related states, so does their
composite. The price is what the composite forgets between stages. Each stage's
obligation is stated for every pair of related states, so all that passes from one
stage to the next is that the two states are related. What an earlier stage
establishes about its result is lost: that \m{check_handler_completed} has just
made the NOP handler pending, or that \m{check_slice_count} has just masked the
disk and NOP handlers. \m{initiate_next} must therefore be non-interfering on
\emph{every} pair of related states, and that fails. Two related states agree on
the counter and the masks but may differ in the private pending bits; if the disk
and NOP handlers are unmasked, the disk handler is pending in one state, and no
secret handler in the other, one state enters S and the other does not.

What is forgotten is the link between the counter and the secret handlers' bits.
The sliced policy maintains it on every state it reaches in which not all masks are
set, that is, at every choice that rule~1 of \m{initiate_next} does not settle:
\begin{enumerate}
\item the NOP mask equals the disk mask;
\item inside an open slice, the NOP handler is pending and the timer masked;
\item outside a slice, the disk and NOP handlers are masked.
\end{enumerate}
With these three conditions, whether a secret handler is ready depends only on the
counter and the masks, which are public: inside a slice, exactly when the disk and
NOP handlers are unmasked; outside it, never. So two related states that satisfy
them agree on whether a secret handler is ready, which is the fact
\m{initiate_next} needs.

Two ways of putting the conditions back fail. $\eqv{V}$ cannot be restricted to the
states that satisfy them, because a characterised equivalence relates every value
to itself. And arguing over reachable states only would give up the per-constructor
structure of the proof. Instead the model writes the conditions into the state:
\m{initiate_next} applies \m{restore_invariant} just before it chooses
(\cref{sec:state}). \m{restore_invariant} reads the counter and, in an open slice,
sets the NOP pending bit and the timer mask, otherwise the disk and NOP masks, and in
both cases copies the disk mask to the NOP mask. Every state it returns satisfies
the three conditions, so the proof of the choice needs to consider only states in
its image. It reads only public fields, so it is itself a routine stage,
$\mathsf{restore\_invariant} \in \NI(\eqv{V},\eqv{V})$.

The proof of \cref{thm:main} needs nothing more. What remains is to show that the
restriction costs nothing: \m{restore_invariant} is the identity wherever the model
applies it, so \m{model_sliced} behaves exactly as the sliced policy without it. Write $v_{es}$ for the state after the events $es$ from the initial state
of \m{model_sliced}, and $c_o(v)$ for the state that \m{initiate_next} receives on
output $o$ in state $v$, after \m{check_scheduler} and the service policy.

\begin{theorem}[\m{restore_invariant_noop}]\label{thm:noop}
Let $\mathit{runtime} \neq 1$. For all events $es$ and outputs $o$, if not all masks
are set in $c_o(v_{es})$, then $\mathsf{restore\_invariant}\;(c_o(v_{es})) =
c_o(v_{es})$.
\end{theorem}

\m{initiate_next} applies \m{restore_invariant} only when not all masks are set, so
it never changes a state the model reaches. The events $es$ are arbitrary, so this
holds whatever the pool emits.

The proof of \cref{thm:noop} is an invariant between steps (\m{sliced_inv}: the disk
and NOP masks agree, are set outside a slice, and a handler is running inside one),
preserved by every event. At the choice point a variant (\m{choice_inv}) also allows
a handler boundary inside a slice, where the masks are open and the NOP handler is
pending; on such states \m{restore_invariant} is the identity.

The hypothesis $\mathit{runtime} \neq 1$ marks where \m{restore_invariant} and the
counter disagree: \m{restore_invariant} treats a closing slice, at \code{Some 0}, as
closed. Normally no choice is made then, because the last run is still in progress.
With one-step handlers the last boundary of a slice falls on that step, and
\m{restore_invariant} masks the handler the boundary has just enabled.
Non-interference is unaffected, but at $\mathit{runtime} = 1$ every slice loses its
last handler run.

private user's slot is among them; its secrecy is carried by its private payload.

\emph{The disk and NOP slots hide which.} One secret pid maps to \code{true} and the
other to \code{false}, so $g \in \NI$ needs \code{true} and \code{false} related at

and the wrapper $\cdot + \one^\Hi$, under which every output, \code{None} included,

emits \code{Some o} in one run and \code{None} in the other, and the NOP slot the

system is in S only from the others.

The dark and light slots of $\Eout$ (\cref{def:io}) carry the payload
equivalences of the hypotheses of \cref{thm:main}; the white shade of the disk and
NOP slots is what this subsection requires.

\subsection{What the proof requires}\label{sec:requirements}
\todo{cut this subsection; the intro's second contributions bullet (the
requirements) cites it and needs rewording when it goes.}

Read as rules for an implementation, the obligations of this section are
sufficient for non-interference: an implementation that follows them can be proved
non-interfering in the same way. We do not claim they are necessary; another choice
of state equivalence would give other rules.
\begin{itemize}
\item The arrival of a secret interrupt may only record that it is pending: by
  $\mathsf{PE}$, the input step may touch nothing but a private bit
  (\cref{sec:state-equiv}).
\item When S is entered, and for how long, must be fixed by public events: two
  related states must agree on whether a secret handler is ready, which takes a
  filler while the slice is open and the masks while it is closed
  (\cref{sec:update,sec:restore}).
\item The interrupt controller is split by secrecy: the secret handlers' pending
  bits are private, and every mask is public, because \m{initiate_next} branches on
  the masks (\cref{sec:state-equiv}).
\end{itemize}
The sliced policy meets all three; an implementation of it has to preserve them.
