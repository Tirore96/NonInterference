\section{The Security Proof}\label{sec:proof}

This section proves \cref{thm:main}: if the scheduler and the public user process are
non-interfering at the public equivalence, and the private user process at the
private one, then \m{model_sliced} is non-interfering at \m{in_equiv} on input and
\m{out_equiv} on output. At the attacker's level $\Lo$ the claim reads as follows. A
disk interrupt is unobservable at $\Lo$ (\cref{sec:interface}), so two input streams
that differ only in disk interrupts must give outputs that \m{out_equiv} relates: at
every step the attacker sees the same U and T steps, and whether the system is in S,
and the two runs may differ only in \emph{which} secret handler runs there. At every
other level each equivalence of the model is equality, and every obligation below
holds trivially; we discuss $\Lo$ only.

The proof applies \cref{thm:composition} to the term of \m{model_sliced}
(\cref{fig:system}) from the outside in. The theorem gives the outermost
equivalences, \m{in_equiv} and \m{out_equiv}; the proof chooses those inside:
$\eqv{E}$ on the events the state receives, $\eqv{V}$ on the state, and $\eqv{B}$
on each gate bit.
\begin{itemize}
\item \emph{Feedback} (\code{map}, \code{loop}; \comp{it:map}, \comp{it:loop}). The
  loop feeds each output back to the state as an event, so \comp{it:loop} needs one
  equivalence on the events going in and coming out. For $\eqv{E}$ we take the sum
  of \m{in_equiv} and \m{out_equiv}: it relates interrupts by \m{in_equiv} and
  outputs by \m{out_equiv}, never an interrupt to an output, and an event is
  unobservable exactly when it is a disk interrupt at $\Lo$. The maps around the
  loop only tag and untag events.
\item \emph{The state} (\code{sta}; \comp{it:sta}). The state update must respect
  $\eqv{V}$. This decides \emph{whether} a secret handler runs, and it is the hard
  obligation (\cref{sec:state-equiv,sec:update,sec:restore}).
\item \emph{The pool} (\code{map}, \code{maybe}, \code{par}; \comp{it:map},
  \comp{it:maybe}, \comp{it:par}). The pool's input map sends every interrupt to
  \code{None}, which the pool ignores and no level sees, and every output to the
  current pid. \code{par} splits the output equivalence into one component per slot.
\item \emph{The slots} (\code{map}, \code{swi}; \comp{it:map}, \comp{it:swi}). Each
  slot's gate must hide \emph{which} secret handler runs (\cref{sec:gating}).
\item \emph{The slot processes.} The scheduler and the user processes are covered
  by the hypotheses of \cref{thm:main}. Each handler is a counter, a \code{map} of a
  \code{sta} of an \code{out}, whose state no input changes.
\end{itemize}

\subsection{The state equivalence}\label{sec:state-equiv}

For the state, \comp{it:sta} asks that the update $f$ be equivalence-preserving,
$f \in \mathsf{PE}(\eqv{E},\eqv{V})$: an unobservable event leaves the state related
to itself; and non-interfering, $f \in \NI(\eqv{E},\eqv{V},\eqv{V})$: related events
take related states to related states (\cref{sec:composition}). The first condition
asks for private fields, the second for public ones. We make a field private only
where a condition forces it, which gives the shading of \cref{fig:state}
(\m{state_type_equiv}):
\begin{itemize}
\item \emph{Pending bits are private.} A disk interrupt is unobservable at $\Lo$ and
  sets the disk pending bit, so by $\mathsf{PE}$ that bit is private. The NOP
  pending bit is private by $\NI$: when a slice opens, the disk handler takes the
  run the NOP handler was queued for, so after that run the NOP handler is pending
  in one state and not in the other.
\item \emph{The current pid is $\mathsf{eqsum}(\text{private}, \text{public})$.} Its
  \code{inl} side holds exactly the two secret handlers (\cref{sec:global-state}),
  and which of them runs may differ between the two states, so the value inside
  \code{inl} is private. $\mathsf{eqsum}$ never relates an \code{inl} to an
  \code{inr}, so \emph{whether} a secret handler runs stays public.
\item \emph{Every other field is public:} the masks, the slice counter, the
  reschedule flag and the previous pid. Nothing forces them private, and
  \m{initiate_next} branches on all of them to compute the next pid, whose tag
  must be public: two states that disagreed on a mask, or on whether a slice is
  open, could enter S in one and not in the other.
\end{itemize}
The same conditions explain why \m{set_pending} sets one bit and stops: any decision
taken on an input step, such as starting a handler or moving the counter, would
change a public field, so everything an interrupt causes waits for a later output
step.

\subsection{The state update}\label{sec:update}

$\mathsf{PE}$ concerns unobservable events only, that is, disk interrupts, which
\m{set_pending} turns into one private bit; it is immediate. The hard obligation is
$\NI$ for the whole update. It splits along the two lanes of \m{state_step}
(\cref{sec:state}), since $\eqv{E}$ never relates an interrupt to an output, and
along the output lane into one goal per stage. On the input lane \m{set_pending}
writes a private bit. On the output lane:
\begin{itemize}
\item \emph{\m{check_scheduler} and the service policy are routine.} They read only
  public fields of the state and the output, so they write the same values into
  both states. In particular, the service policy reads only the timer handler's
  output, which is public; this is what the restriction of \cref{sec:sliced} buys.
\item \emph{\m{initiate_next} decides whether S is entered.} The timer's readiness
  is public, so both states agree on it. Otherwise, in each state the secret
  handler ready to start is the disk handler, the NOP handler, or none. Disk in one
  state and NOP in the other is harmless: both start an \code{inl} pid, whose value
  is private. A secret handler in one state and none in the other is fatal: one
  state enters S and the other continues a user process.
\end{itemize}
So the stage needs one fact: two related states, about to choose, either both have
a secret handler ready or neither has. The ordinary policy fails here and in the
service policy. \m{immediate_service} unmasks when any handler completes, the disk
handler included, so it writes public masks from a private output. And
\m{initiate_next} meets the fatal case: a bold arrow of \cref{fig:policy-ordinary}
taken in one run only, which is the counterexample of \cref{thm:leak}.

In the states the sliced policy reaches, the public counter gives the fact: while a
slice is open the NOP handler is ready, and otherwise neither secret handler is. But
$\NI$ quantifies over all pairs of related states, reachable or not.

\subsection{Restoring the invariant}\label{sec:restore}

Restricting $\eqv{V}$ to the states that satisfy the invariant is not possible: a
characterised equivalence relates every value to itself. Arguing over reachable
states only would give up the per-constructor structure of the proof. Instead,
\m{initiate_next} applies \m{restore_invariant} just before it chooses
(\cref{sec:state}), so the proof of this stage needs to consider only states
that satisfy the invariant. It writes into the state the masks that
go with the counter: in an open slice it sets the NOP pending bit and the timer
mask, otherwise the disk and NOP masks, and in both cases it copies the disk mask to
the NOP mask. It reads only public fields, so it does the same to two related
states, and afterwards either both have a secret handler ready or neither has. This
is the fact \m{initiate_next} needs.

It remains to show that \m{restore_invariant} is the identity wherever it is
applied, so that it restricts what the proof considers without changing what the
model does. Write $v_{es}$ for the state after the events $es$ from the initial state
of \m{model_sliced}, and $c_o(v)$ for the state that \m{initiate_next} receives on
output $o$ in state $v$, after \m{check_scheduler} and the service policy.

\begin{theorem}[\m{restore_invariant_noop}]\label{thm:noop}
Let $\mathit{runtime} \neq 1$. For all events $es$ and outputs $o$, if not all masks
are set in $c_o(v_{es})$, then $\mathsf{restore\_invariant}\;(c_o(v_{es})) =
c_o(v_{es})$.
\end{theorem}

\m{initiate_next} applies \m{restore_invariant} only when not all masks are set, so
it never changes a state the model reaches. The events $es$ are arbitrary, so this
holds whatever the pool emits.

The proof of \cref{thm:noop} is an invariant between steps (\m{sliced_inv}: the disk
and NOP masks agree, are set outside a slice, and a handler is running inside one),
preserved by every event. At the choice point a variant (\m{choice_inv}) also allows
a handler boundary inside a slice, where the masks are open and the NOP handler is
pending; on such states \m{restore_invariant} is the identity.

The hypothesis $\mathit{runtime} \neq 1$ marks where \m{restore_invariant} and the
counter disagree: \m{restore_invariant} treats a closing slice, at \code{Some 0}, as
closed. Normally no choice is made then, because the last run is still in progress.
With one-step handlers the last boundary of a slice falls on that step, and
\m{restore_invariant} masks the handler the boundary has just enabled.
Non-interference is unaffected, but at $\mathit{runtime} = 1$ every slice loses its
last handler run.

\subsection{Gating a slot}\label{sec:gating}

Inside \code{sta}, \code{par} gives each slot its own component of the output
equivalence, and each slot is a \code{swi} whose gate bit a \code{map} computes from
the pid. Both obligations depend on the equivalence $\eqv{B}$ on the gate bit, which
the proof chooses per slot. \comp{it:map} requires the gate map to be
unobservable-preserving, sending unobservable pids to unobservable bits, and
\comp{it:swi} requires, at every level, that the observer be aware of the gate or
oblivious to the slot:
\[
\ell \in \Aw(\mathsf{true}, \eqv{B}) \;\cup\;
  \Ob(\mathsf{swi}\;b\;p,\; \mathsf{eqmaybe}(\Aw(\mathsf{true},\eqv{B}),\eqv{O})).
\]
Awareness means a bit related to \code{true} is \code{true} and observable, so the
observer can trust the gate; obliviousness means it sees none of the slot's outputs.
At $\Lo$ the two secret pids are unobservable, and the slots fall into two groups.

\emph{Every other slot shows whether.} Both secret pids map to \code{false}, so the
gate equivalence \m{false_equiv}, in which only \code{false} is unobservable, is
preserved, and the observer is aware at every level. The output wrapper is
$\mathsf{eqmaybe}(\{\Lo,\Hi\},\cdot)$: the attacker tells \code{Some} from
\code{None}, so it sees whether the slot ran. While a secret handler runs, all these
slots emit \code{None}; this is how the attacker sees that the system is in S. The
private user's slot is among them; its secrecy is carried by its private payload.

\emph{The disk and NOP slots hide which.} One secret pid maps to \code{true} and the
other to \code{false}, so both bits must be unobservable: $\eqv{B}$ is the private
equivalence, and awareness fails at $\Lo$. The proof uses obliviousness, and gets
it by construction: both slots get a private payload and the wrapper
$\mathsf{eqmaybe}(\{\Hi\},\cdot)$, under which every output, \code{None} included,
is unobservable at $\Lo$. This is needed, because when a slice opens the disk slot
emits \code{Some o} in one run and \code{None} in the other, and the NOP slot the
reverse. The attacker learns nothing from these two slots, and learns that the
system is in S only from the others.

The dark and light shades of \m{out_equiv} (\cref{sec:interface}) are the payload
equivalences of the hypotheses of \cref{thm:main}; the white shade of the disk and
NOP slots is what this subsection requires.

\subsection{What the proof requires}\label{sec:requirements}

Read as rules for an implementation, the obligations of this section are
sufficient for non-interference: an implementation that follows them can be proved
non-interfering in the same way. We do not claim they are necessary; another choice
of state equivalence would give other rules.
\begin{itemize}
\item The arrival of a secret interrupt may only record that it is pending: by
  $\mathsf{PE}$, the input step may touch nothing but a private bit
  (\cref{sec:state-equiv}).
\item When S is entered, and for how long, must be fixed by public events: two
  related states must agree on whether a secret handler is ready, which takes a
  filler while the slice is open and the masks while it is closed
  (\cref{sec:update,sec:restore}).
\item The interrupt controller is split by secrecy: the secret handlers' pending
  bits are private, and every mask is public, because \m{initiate_next} branches on
  the masks (\cref{sec:state-equiv}).
\end{itemize}
The sliced policy meets all three; an implementation of it has to preserve them.
