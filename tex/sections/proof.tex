\section{The Security Proof}\label{sec:proof}

In the terms of \cref{sec:designs}, the sliced policy makes \emph{whether} the system
is in S public, and keeps only \emph{which} secret handler runs there private. In the two sliced runs of \cref{fig:run-sliced}, a
secret handler runs at steps 7 to 10 in both; the runs differ only in which handler
runs at steps 7 and 8. This section proves that the same holds for every pair of
runs the attacker should not tell apart, and that nothing else reveals the secret.

\subsection{Gating a slot}\label{sec:gating}

Each slot is a \code{swi} whose gate bit is computed from the pid by a \code{map}. Two
obligations remain per slot, both parameterised by an equivalence $\eqv{B}$ on the gate
bit that the proof may choose. \m{map_NI} requires the gate map to be unobservable-preserving,
sending unobservable pids to unobservable bits (\m{f_PU}), and \m{swi_NI} requires, at every level, that the
observer be aware of the gate or oblivious to the slot:
\[
\ell \in \Aw(\mathsf{true}, \eqv{B}) \;\cup\;
  \Ob(\mathsf{swi}\;b\;p,\; \mathsf{eqmaybe}(\Aw(\mathsf{true},\eqv{B}),\eqv{O})).
\]
Awareness means a bit related to \code{true} is \code{true} and observable, so the observer can
trust the gate. Obliviousness means the observer sees none of the slot's outputs,
whatever the input does.

At $\Lo$ the two pids of the secret handlers are unobservable. For every slot except
the disk and NOP slots, both map to \code{false}, so a $\eqv{B}$ in which \code{false}
alone is unobservable satisfies \m{f_PU}; we call it \m{false_equiv}. Under
\m{false_equiv} the observer is aware at every level, and the obligation is discharged
without a case split. These slots are wrapped in $\mathsf{eqmaybe}(\{\Lo,\Hi\},\cdot)$, under which
the attacker tells \code{Some} from \code{None}: it sees whether they ran. At step 7 of
\cref{fig:run-sliced} they all emit \code{None} in both sliced runs, because a secret
handler runs; this is the \emph{whether}, and it is public. The private user's slot is
among them. Its gate is public, and its secrecy is carried by its \m{private_equiv}
payload.

For the disk and NOP slots, one secret pid maps to \code{true} and the other to
\code{false}, so \m{f_PU} demands that both bits be unobservable, which leaves only
\m{private_equiv}. Then \code{true} is unobservable at $\Lo$ and awareness fails there,
so the proof uses obliviousness. At step 7 the disk slot emits \code{Some o} in one
run and \code{None} in the other, and the NOP slot the reverse, so both must be
unobservable at $\Lo$. Under $\mathsf{eqmaybe}(\Aw(\mathsf{true},\eqv{B}),\eqv{O})$, \code{None} is
unobservable exactly when the gate is hidden, and \code{Some o} exactly when the payload is. Both slots
therefore get a private payload and the wrapper $\mathsf{eqmaybe}(\{\Hi\},\cdot)$, under which a
handler run and a step in which nothing happened are the same observation. This is
the \emph{which}, and it is hidden. The NOP slot is classified like the disk slot
because a slice run is filled by one or the other.

\subsection{The state}\label{sec:state-equiv}

\todo{$\doteq^E$ (events) appears without being introduced.}\m{sta_NI} imposes two conditions on the state update $f$, and they pull in opposite
directions. \m{f_EP} requires that an unobservable input leave the state related to
itself, and \m{fv_NI} that related events map related states to related states:
\[
i \eqv{I}_\ell \unobs \Rightarrow f\,i\,v \eqv{V}_\ell v,
\qquad
e \eqv{E}_\ell e' \wedge v \eqv{V}_\ell v' \Rightarrow f\,e\,v \eqv{V}_\ell f\,e'\,v'.
\]
A disk interrupt is unobservable at $\Lo$ and sets the disk pending bit, so by
\m{f_EP} that bit must be private. \m{initiate_next} branches on the mask bits, so by
\m{fv_NI} they must be public: two related states that disagreed there would take
different branches. Both hold only if the interrupt controller is classified per
bit: the disk and NOP pending bits are private and every mask bit is public
(\cref{tab:state-equiv}). The same constraint explains why \m{set_pending} sets one
bit and stops. Any decision taken on an input step, such as starting a handler or
moving the slice counter, would disturb a public field, so everything an interrupt
causes is deferred to a later output step, where the input is no longer the thing
being varied.

The current pid carries the idea directly. Its \code{inl} side holds exactly the two
secret handlers (\cref{sec:global-state}), and it is related by
\code{eqsum private_equiv public_equiv}. Since \m{eqsum} never relates an \code{inl} to
an \code{inr}, \emph{whether} a secret handler runs is visible, as is every public pid;
\m{private_equiv} hides the bit inside \code{inl}, which is \emph{which} one runs.

The state rows of \cref{fig:run-sliced} show the secret moving through the state with
the phases of \cref{fig:phases} (\m{sliced_states_with_dI}). While the slice is
closed, it is the disk pending bit. When the slice opens, the disk handler takes the
run the filler was queued for, so during the first run it is which handler runs and
the NOP pending bit. From the second run on, the two states agree. The public rows,
the counter and the timer mask, never differ. The secret survives only in the private user process, which
the disk handler notified.

The core obligation is \m{fv_NI} for the whole transition. The transition is a sum,
\m{set_pending} on interrupts and a pipeline of stages on outputs, and the event
equivalence never relates an interrupt to an output. So the goal splits along the
sum, and a composition lemma (\m{fv_NI_comp}) splits the pipeline into one goal per
stage. Three stages are routine: \m{set_pending} sets one private bit, and
\m{check_scheduler} and \code{service_policy} read only public fields of the state
and the output, and write the same values into both states. For the service policy
this is what the restriction of \cref{sec:sliced} buys: \m{immediate_service} reads
the disk handler's output.

handler runs is decided. The timer is public, so both states agree on it. Otherwise,
in each state the secret handler ready to start is the disk handler, the NOP handler,
or none. Disk in one state and NOP in the other is harmless: both start an \code{inl}
pid, which \m{private_equiv} hides. A secret handler in one state and none in the other
is fatal: one state starts a handler and the other continues a user process, and the
attacker sees the difference. The slice counter is public, so related states are in
the same phase of \cref{fig:phases}, and in the states the model reaches each phase
fixes readiness: while a slice is open the NOP handler is ready, and while it is
closed neither secret handler is. That rules the fatal case out. But a
stage-by-stage proof must hold for all pairs of related states, not only those the
model reaches, and so cannot use it.

\subsection{Restoring the invariant}\label{sec:restore}

\todo{`phase of Fig.~7': Fig.~7 now draws U/T/S with counter values, not phases. Align the words throughout V (`open slice' = in S).}The function \m{restore_invariant} makes the phase fix readiness in every state.
Just before \m{initiate_next} chooses, it writes the masks of the current phase of
\cref{fig:phases} into the state: in an open slice it sets the NOP pending bit and
the timer mask, otherwise the disk and NOP masks, and in both cases it copies the
disk mask to the NOP mask. It reads only public fields, so it does the same to two
related states, and afterwards either both have a secret handler ready or neither
has. This discharges \m{initiate_next}. In the states the model reaches, the policy
has already done all of this (\cref{sec:sliced}), and we prove that
\m{restore_invariant} never changes them.

\todo{hard to parse. Keep the formal condition (`not all masks are set' is exactly \code{initiate\_next}'s guard) and add the gloss `that is, no handler is running', and `reachable' for the events clause.}\begin{theorem}[\m{restore_invariant_noop}]\label{thm:noop}
Let $\mathit{runtime} \neq 1$. For every sequence of events $es$ from the initial
state of \m{model_sliced}, and every output $o$, let $w$ be the state that
\m{initiate_next} receives on $o$ after $es$. If not all masks are set in $w$, then
$\mathsf{restore\_invariant}\;w = w$.
\end{theorem}

The events $es$ are arbitrary, so the theorem holds whatever the pool emits. The proof states the invariant
between steps, shows that every event preserves it, and shows that at the choice
point a slightly weaker invariant holds,\todo{which weaker invariant? One line, or drop the remark.} on which \m{restore_invariant} is the
identity. One small lemma per stage of the pipeline does the bookkeeping.

The hypothesis $\mathit{runtime} \neq 1$ marks where \m{restore_invariant} and the
phases of \cref{fig:phases} disagree: \m{restore_invariant} treats a closing slice as
closed. Normally no choice is made while a slice is closing, because its last run is
still in progress. With one-step handlers, the last boundary of a slice falls on the
step that ticks the counter to zero, so \m{restore_invariant} masks the handler that
boundary has just enabled. Non-interference is unaffected (\cref{thm:main} has no
such hypothesis), but at $\mathit{runtime} = 1$ every slice loses its last handler
run.
