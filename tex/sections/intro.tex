\section{Introduction}\label{sec:intro}

Interrupts tell an operating system that something happened: a disk transfer
completed, a packet arrived, a timer expired. Some of these events are secret:
whether a process just received data from the disk may reveal what it is doing.
Servicing an interrupt takes time from whichever process was scheduled, so an
operating system that keeps such an event secret must also hide when its handler
runs, and for how long.

\emph{Immediate} interrupt handling, the usual kind, does not hide it: as soon as an
interrupt can be serviced, its handler runs for a few steps, displacing the scheduled
process, which then resumes. Suppose a public process keeps issuing requests whose results an
attacker can see. While the handler runs those requests stop, and the attacker sees
a gap in the stream exactly as long as the handler (\cref{fig:leak}). The interrupt
has leaked through the \emph{schedule}, although the attacker never sees the
schedule itself: the gap is in the public process's own output. Timing leaks
through interrupt handling of this kind arise in several operating
systems \todo{examples, with citations}.

Leaks like this are timing channels, which operating-systems work measures and
mitigates~\cite{cock2014,ge2019}. We take the view of information-flow
control~\cite{sabelfeld2003}, where Goguen and Meseguer's
non-interference~\cite{goguen1982} states the absence of a leak: varying what the
attacker may not see must not change what it does see. For timing
leaks, what the attacker sees includes when each output appears~\cite{agat2000}. Our
attacker watches the output of the public process, and when it appears.

Existing results leave this problem open. Non-interference proofs for verified
kernels such as seL4 exclude timing channels~\cite{murray2012,murray2013}, which
remain measurable~\cite{cock2014}. Language-based
work closes timing channels in programs~\cite{agat2000,askarov2010} and asks which
programs are secure under a given scheduler~\cite{smith1998,mantel2010}, but leaves out
the interrupt mechanism, which decides when handlers preempt the scheduled process.
To our knowledge, no proof shows an interrupt policy timing-sensitive
non-interfering\todo{confirm}.

We build such a proof in the process calculus of Rafnsson, Jia and
Bauer~\cite{rafnsson2017}, whose non-interference is timing-sensitive and whose
theorems compose: if the parts of a process are non-interfering, so is the whole. We model interrupt handling and process scheduling as
one closed process (\cref{fig:system}): the user processes, the scheduler and the
handlers run in a pool, and a global state decides at each step which of them runs.
The model is generic in its \emph{interrupt policy}, the part that decides when
handlers may run. With the immediate policy the model is interfering, with \cref{fig:leak} as the counterexample. Our
policy fixes when secret interrupts are handled, and for how long, by public events.
In our model the timer interrupt is public, and when its handler completes, the
policy allocates a time slice in which secret interrupts may be handled, as in time
protection~\cite{ge2019}\todo{more citations for time slices?}; a dummy handler
fills whatever time they leave unused. Only \emph{which} secret interrupt is handled
depends on the secret.

That this policy is secure is intuitive; proving it is not. The secret still changes
the state: it sets a pending bit, decides which handler takes a run, and changes what
the private user process does next. The proof must show that none of this ever decides
whether, or for how long, secret interrupts are handled. Composition reduces it to the parts
of the model, and an invariant on the states the policy reaches does the rest.

\paragraph{Contributions}
\begin{itemize}
\item A mechanised counterexample: immediate interrupt handling is interfering
  (\m{model_immediate_not_NI}), and the leak needs only the output of the public
  process (\m{model_immediate_publicview_not_NI}) (\cref{sec:leak}).
\item A mechanised, timing-sensitive non-interference proof for the sliced policy
  (\m{model_sliced_NI}), for every non-interfering scheduler and pair of user
  processes, every handler length and every slice size
  (\cref{sec:designs,sec:proof}). The proof is compositional: one generic theorem per
  constructor of the model leaves two steps specific to interrupt handling
  (\cref{lem:state-cell,lem:slot}).
\item Three obligations on an interrupt policy that suffice for non-interference in
  our model, with the sliced policy as one instance (\cref{thm:policy}).
\item A mechanisation in Rocq of the calculus and its composition theorems
  (\cref{sec:mechanisation}), over finite traces and proved equivalent to the
  original coinductive definition, extended with sum types and a composition theorem
  for state cells under an invariant.
\end{itemize}

\Cref{sec:background} recalls the calculus, \cref{sec:model} builds the model,
\cref{sec:designs} gives the two policies and the leak, and \cref{sec:proof} proves
the sliced policy secure. \Cref{sec:mechanisation,sec:related,sec:conclusion} cover
the mechanisation, related work and conclusions.
