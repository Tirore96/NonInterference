To show examples with interferences we need to invert reduceI/reduceO and show a contradiction.
This requires I O and proc I O to be terms and not types.

For processes that use type operators like Times and Sum we must annoate this in construction of the process, because RoqC cannot infer
which t0 t1 : Ty, has [Times t0 t1] = A * B.

This works fine, although a bit tedious.

An idea! Now that we are sprinkly typing annotations onto our processes, we might as well push some more information into the type constructors,
distinguishing by Times, Times_L, Times_LR,... which characterised equivalence we want, e.g. eqpair, eqpair_L, eqpair_LR...

Finally, since we only plan on using the process language to build processes that can be proved to be NI using the existing theorems (one for each construct), we may additionally push this proof-relelvant information into the process definition.

An example:
@sta
     : forall I O V : Ty,
     ([I] -> [V] -> [V]) ->
     ([O] -> [V] -> [V]) ->
     [V] ->
     Proc (Times_R V I) O -> (*We don't care about distinguishability in V*)
     Proc I (Times V O)

We have effectively made the characterised equivalence a function of Ty, so we may be able to eliminate the characterised equvialence as a parameter in all definitions
