IMPLEMENTATION NOTES — STATEFUL OS INTERRUPT MODELING
======================================================

We have updated the OS process pool and scheduler model in `current_files/current.v` to mimic a CPU-like interrupt controller, ensuring serialization and preventing timing-channel leaks. Below is a detailed summary of the modifications made.

1. Scheduler Output Refactoring
-------------------------------
* Originally, the scheduler (`good_schedulerp`) outputted `Times Nat Nat` to specify which process to turn off and which to turn on.
* We simplified the scheduler to output a single `Nat` indicating the next scheduled process. 
* This decouples the scheduling policy (handled by the scheduler process itself) from the preemption/serialization mechanism (handled by the outer state wrapper).

2. The Stateful CPU Register Wrapper (V_state)
----------------------------------------------
* We introduced `V_state := Times (Times (Times Bool Bool) (Times Bool Bool)) (Times Nat Bool)`, representing the registers:
  `((timer_received, disk_received), (timer_pending, disk_pending), (p_sched, handler_active))`
* Latch Registers (`timer_received`, `disk_received`): Latch incoming interrupt signals *during* the execution of a process. The running process is not preempted mid-cycle.
* Pending Registers (`timer_pending`, `disk_pending`): Checked at step boundaries to schedule the scheduler or handler in the subsequent step.
* Scheduled Process (`p_sched`): A single `Nat` tracking the process chosen by the scheduler.
* Handler Status (`handler_active`): Boolean flag tracking whether the private interrupt handler is running.

3. Transitions and Input Override
---------------------------------
* `f_state` (Input transition): Latches incoming interrupt signals on the bus into the latch registers.
* `override_pool_input` (Input override): Maps the registers to the process pool schedule:
  - If `timer_pending` is set: activates the scheduler (index 4) with `Some TimerInterrupt` input.
  - If `handler_active` is set: activates the handler (index 1) with `Some DiskInterrupt` input.
  - Otherwise: runs the scheduled process `(p_sched, p_sched)`.
* `g_state` (Output transition): Clears and promotes registers at the end of each step (e.g. promoting received interrupts to pending, resetting handler flags when the handler outputs, and updating `p_sched` to the scheduler's output value).

4. Router & Type Compatibility Fixes
------------------------------------
* `my_f_route_good` was updated to handle the new `Nat` scheduler output by returning `((sch, sch), none4)` in the first branch.
* In the handler-completion routing branch `(_ ,(None,(None,Some handl)))`, we changed the scheduler input from `Some (inr handl)` (which had a type mismatch) to `None` (matching the expected `option Interrupt` type since `my_f_I 3 = TInterrupt`).
* The scheduler pattern match on `ih` (of type `TInterrupt` / `Interrupt`) was made exhaustive by adding the `DiskInterrupt => b` branch.

5. Trace Adjustments
--------------------
* `newtrace'` (internal) was updated to expect a single `Nat` (e.g. `out0 3` instead of `out0 (3,3)`) for scheduler outputs.
* Both `newtrace'` and `newtrace_wrap` are verified to represent serialization where exactly one process is active per cycle.

6. Manual Relation Specifications
---------------------------------
* In the trace lemmas (`newtrace'_trace` and `newtrace_trace`), we replaced `to_rel _` with manually constructed relations using the core combinators:
  - World Observable Relation:
    `eqmaybe (eqsum_LR (publicRel TPublicOutput) (semiprivateRel TTypeSyscall))`
  - Internal Pool Relation:
    `eqpair_LR (eqmaybe (publicRel Nat)) (eqpair_LR (eqmaybe (publicRel TPublicOutput)) (eqpair_LR (eqmaybe (semiprivateRel TTypeSyscall)) (eqmaybe (semiprivateRel THandlerOutput))))`
